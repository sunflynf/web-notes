# Serverless Cheatsheet

## At a glance

| | |
|---|---|
| What it is | Run code on demand (Functions-as-a-Service) without managing servers; scale to zero, pay per request/duration |
| Use it for | Event handlers (S3/queue/DB changes), small HTTP APIs, cron jobs, glue between managed services, webhooks |
| Latest stable | Serverless Framework v4.46.0 (released 2026-10-28); newest GA AWS Lambda runtimes `nodejs24.x` and `python3.14` (`nodejs26.x` / `python3.15` in public preview) - checked 2026-10-31 |
| Official docs | [AWS Lambda](https://docs.aws.amazon.com/lambda/) - [Azure Functions](https://learn.microsoft.com/azure/azure-functions/) - [Cloud Run functions](https://cloud.google.com/run/docs/functions/comparison) - [Serverless Framework](https://www.serverless.com/framework/docs) |

## Core concepts

- **Function** - a handler invoked per event; stateless, short-lived, configured with memory/timeout/env/IAM role.
- **Trigger / event source** - HTTP (API Gateway, Function URL), queue (SQS), storage (S3), stream (Kinesis/DynamoDB Streams), schedule (EventBridge Scheduler).
- **Cold start** - first request on a new instance pays init time (runtime boot + your top-level code); warm instances are reused.
- **Concurrency** - one instance handles one request at a time on Lambda; Azure Functions and Cloud Run functions can serve several per instance.
- **Invocation types** - synchronous (caller waits), asynchronous (queued, retried, then DLQ / on-failure destination), poll-based (event source mapping).
- **Execution role / identity** - permissions come from the function's role (AWS IAM role, Azure managed identity, GCP service account).
- **Layers / extensions** - share dependencies or add sidecar agents (Lambda layers and extensions).
- **Hosting plans** - Azure: Flex Consumption (recommended), Premium, Dedicated; GCP: functions are deployed as Cloud Run services.

### Platform comparison

| | AWS Lambda | Azure Functions | Cloud Run functions |
|---|---|---|---|
| Max timeout | 15 min | Flex Consumption: 30 min default, can be unbounded (HTTP response limit 230 s) | HTTP up to 60 min, event-driven up to 9 min |
| Memory | 128 MB - 10,240 MB | per plan (Flex: 512 MB / 2 GB / 4 GB instances) | up to 32 GiB |
| Concurrency per instance | 1 | many (per-instance concurrency) | up to 1000 |
| HTTP entry | API Gateway / Function URL / ALB | built-in HTTP trigger | built-in HTTPS URL |
| Local dev | SAM CLI, Serverless Framework | Azure Functions Core Tools (`func`) | Functions Framework, `gcloud run deploy --source` |

## Syntax & commands

```javascript
// AWS Lambda - Node.js (ESM), handler = index.handler
export const handler = async (event, context) => {
  return { statusCode: 200, body: JSON.stringify({ hello: "world" }) };
};
```

```python
# AWS Lambda - Python, handler = app.handler
import json

def handler(event, context):
    return {"statusCode": 200, "body": json.dumps({"hello": "world"})}
```

```yaml title="serverless.yml"
service: hello-api
provider:
  name: aws
  runtime: nodejs24.x
  region: ap-southeast-1
  memorySize: 512
  timeout: 10
functions:
  hello:
    handler: index.handler
    events:
      - httpApi:
          path: /hello
          method: get
  nightly:
    handler: jobs.nightly
    events:
      - schedule: cron(0 2 * * ? *)
```

```bash
# Serverless Framework v4 (needs a free Serverless account / license key for orgs over the free threshold)
npm i -g serverless
serverless deploy                  # whole stack (CloudFormation)
serverless deploy function -f hello
serverless invoke -f hello --log
serverless logs -f hello --tail
serverless dev                     # proxy live AWS events to local code
serverless remove

# AWS CLI / SAM
aws lambda invoke --function-name hello out.json && cat out.json
aws lambda update-function-code --function-name hello --zip-file fileb://dist.zip
sam init && sam build && sam local invoke && sam deploy --guided

# Azure Functions Core Tools
func init MyApp --worker-runtime node && func new --template "HTTP trigger" --name hello
func start
func azure functionapp publish my-func-app

# Google Cloud
gcloud run deploy hello --source . --function hello --base-image nodejs24 --region asia-southeast1
```

## Common patterns

| Pattern | How |
|---|---|
| HTTP API | API Gateway HTTP API / Function URL -> Lambda; or Azure HTTP trigger; or Cloud Run function URL |
| Queue worker | SQS -> Lambda event source mapping with batch size + partial batch failure (`ReportBatchItemFailures`) |
| File processing | S3 `ObjectCreated` / Blob trigger / Eventarc Cloud Storage event -> function |
| Scheduled job | EventBridge Scheduler / timer trigger (NCRONTAB) / Cloud Scheduler |
| Fan-out | SNS or EventBridge -> many functions; Step Functions / Durable Functions / Workflows for orchestration |
| Reduce cold starts | Smaller bundles, init SDK clients outside the handler, SnapStart (Java/Python/.NET), provisioned concurrency / always-ready instances |

## Gotchas

- **Timeouts chain**: API Gateway integration timeout defaults to 29 s, so a 15-minute Lambda behind it still fails the HTTP call.
- **Retries cause duplicates** - async and stream invocations retry; make handlers **idempotent**.
- **Recursive loops** (function writes to the bucket that triggers it) burn money; Lambda detects some loops, don't rely on it.
- **DB connections** - thousands of concurrent instances exhaust a database; use RDS Proxy / connection pooling or a serverless DB.
- **VPC access** adds networking setup (ENIs, NAT for Internet egress); only attach a VPC when needed.
- **/tmp is ephemeral** (Lambda default 512 MB, up to 10 GB) - not a database.
- **Runtime deprecation** - managed runtimes are deprecated after the language's EOL; patches stop, then function create and later update are blocked (at least 30 / 60 days after deprecation). Existing functions keep running.
- **Payload limits** - Lambda sync request/response 6 MB, async event 1 MB (raised from 256 KB in 2025); larger data goes through S3.
- **Serverless Framework v4 licensing** - free for individuals and orgs under the revenue threshold; v3 is no longer maintained.

## What's new in recent releases

- **Serverless Framework 4.4x** (2026): frequent minor releases (4.44 on 2026-10-14, 4.45 on 2026-10-20, 4.46 on 2026-10-28); v4 ships TypeScript/esbuild bundling built in and `serverless dev` mode.
- **Lambda preview runtimes** (Aug 2026): first public-preview managed runtimes, `nodejs26.x` and `python3.15`; not for production, GA targeted for November 2026 (Node.js 26 only after it reaches Active LTS).
- **Lambda Node.js 24** (Nov 2025): `nodejs24.x` on Amazon Linux 2023, supported until 2028-04-30 (deprecation date).
- **Lambda Python 3.14** (Nov 2025): `python3.14` on Amazon Linux 2023, supported until 2029-06-30.
- **Google Cloud Functions -> Cloud Run functions** (Aug 2024): functions now deploy as Cloud Run services; `gcloud functions` still works but `gcloud run deploy --function` is the new path.
- **Azure Functions Flex Consumption** (GA 2024): fast scale, VNet integration, always-ready instances; the older Linux Consumption plan is scheduled to retire (2028-09-30), so new apps should use Flex.
