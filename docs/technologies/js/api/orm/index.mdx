## Notes

- **[Sequelize](https://sequelize.org/)**: A mature ORM with wide database support and robust features like transactions and migrations. Best for projects prioritizing stability and broad compatibility.
- **[Prisma](https://www.prisma.io/)**: A modern ORM with a focus on type safety and developer experience, using a unique schema-based approach. Ideal for TypeScript projects but less flexible for raw SQL.
- **[TypeORM](https://typeorm.io/)**: Offers flexibility with both Active Record and Data Mapper patterns, strong TypeScript support via decorators. Suited for complex applications but may have maintenance inconsistencies.
- **[Objection.js](https://vincit.github.io/objection.js/)**: Built on Knex.js, it excels in complex SQL queries and relational data handling. Best for developers comfortable with SQL who need a lightweight ORM.
- **[Drizzle ORM](https://orm.drizzle.team/)**: A lightweight, SQL-first ORM with schema defined in TypeScript code, offering high performance and serverless compatibility. Ideal for developers who prefer SQL control and minimal abstraction, but requires SQL familiarity and careful schema management.

**Further Reading:**

- [Drizzle vs Prisma](https://www.bytebase.com/blog/drizzle-vs-prisma/)

## Side by side

One task in every tool: find a user by email together with their posts. The tools fall into two groups:

- **ORM**: [Prisma](./prisma.md), [Drizzle](./drizzle.md), [TypeORM](./type-orm.mdx) and [Sequelize](./sequelize.mdx) map tables to models or schemas and load relations for you.
- **Query builder / driver**: [Knex.js](../query-builder/knexjs.md) builds SQL with a chainable API and [node-postgres](../query-builder/node-postgres.md) sends SQL you write yourself. Both return flat rows, so a join repeats the user on each post row.

Each snippet assumes the schema or models are already defined (see the tool's own page).

// Prisma ORM 7 style (prisma/schema.prisma defines User and Post)
const user = await prisma.user.findUnique({
  where: { email: "user@example.com" },
  include: { posts: true },

<TabItem value="drizzle" label="Drizzle">

```ts
import { defineRelations } from "drizzle-orm";

// Relations (users and posts are the pgTable definitions)
export const relations = defineRelations({ users, posts }, (r) => ({
  users: { posts: r.many.posts() },
  posts: {
    author: r.one.users({ from: r.posts.authorId, to: r.users.id }),
  },
}));

const db = drizzle(process.env.DATABASE_URL!, { relations });

const user = await db.query.users.findFirst({
  where: { email: "user@example.com" },
  with: { posts: true },
});
```

`verify`: the Drizzle docs show `where` with `findMany` and `with` with `findFirst`, not both on one call, and `r.many.posts()` may need `from`/`to` in a schema with several relations. Sources: [Relations v2](https://orm.drizzle.team/docs/relations-v2), [Relational queries](https://orm.drizzle.team/docs/rqb).

Full note: [Drizzle](./drizzle.md).

</TabItem>

<TabItem value="knex" label="Knex.js">

```js
const rows = await db("users")
  .leftJoin("posts", "users.id", "posts.user_id")
  .where("users.email", "user@example.com")
  .select("users.*", "posts.id as post_id", "posts.title as post_title");
// one row per post; a user without posts gives one row with null post columns
```

`verify`: `leftJoin` takes the same arguments as `join` in the docs. Source: [Knex query builder](https://knexjs.org/guide/query-builder.html).

Full note: [Knex.js](../query-builder/knexjs.md).

const text = `
