Tổng quan Bảo mật

Trực quan hóa các lớp bảo mật bạn sẽ xây dựng cho máy chủ của mình.

1. Kết nối & Bảo mật SSH

SSH là cổng vào máy chủ của bạn. Việc bảo vệ nó là bước quan trọng nhất. Phương pháp xác thực bằng khóa (SSH Key) an toàn và tiện lợi hơn nhiều so với mật khẩu truyền thống, giúp chống lại các cuộc tấn công dò mật khẩu tự động.

Các bước chính:

1. Tạo cặp khóa SSH trên máy của bạn (Client)

Lệnh này tạo một cặp khóa RSA 4096-bit, một tiêu chuẩn mạnh mẽ cho bảo mật.

ssh-keygen -t rsa -b 4096 -C "email_cua_ban@example.com"
2. Sao chép khóa công khai lên máy chủ (Server)

Sử dụng `ssh-copy-id` là cách đơn giản và an toàn nhất, nó sẽ tự động thiết lập quyền truy cập chính xác.

ssh-copy-id ten_nguoi_dung@dia_chi_ip_may_chu
3. Vô hiệu hóa đăng nhập bằng mật khẩu (Trên Server)

Sau khi chắc chắn bạn có thể đăng nhập bằng khóa SSH, hãy vô hiệu hóa mật khẩu để loại bỏ rủi ro. Chỉnh sửa tệp `/etc/ssh/sshd_config`: 

PasswordAuthentication no
PubkeyAuthentication yes
PermitRootLogin no

Sau đó, khởi động lại dịch vụ SSH:

sudo systemctl restart sshd

2. Cài đặt Cơ sở dữ liệu

Mỗi ứng dụng đều cần một nơi để lưu trữ dữ liệu. Dưới đây là hướng dẫn cài đặt và cấu hình bảo mật ban đầu cho các hệ quản trị cơ sở dữ liệu phổ biến. Hãy chọn loại phù hợp với dự án của bạn.

1. Cài đặt MySQL Server

sudo apt update && sudo apt install mysql-server -y

2. Chạy Script bảo mật

Bước này cực kỳ quan trọng để thiết lập mật khẩu root, xóa người dùng ẩn danh và các cấu hình mặc định không an toàn khác.

sudo mysql_secure_installation

3. Tạo người dùng và cơ sở dữ liệu cho ứng dụng

Đăng nhập với root và thực hiện các lệnh SQL sau. Luôn tạo người dùng riêng cho ứng dụng thay vì dùng `root`. 

CREATE DATABASE my_app_db;
CREATE USER 'my_app_user'@'localhost' IDENTIFIED BY 'mat_khau_manh';
GRANT ALL PRIVILEGES ON my_app_db.* TO 'my_app_user'@'localhost';
FLUSH PRIVILEGES;
EXIT;

1. Cài đặt PostgreSQL

sudo apt update && sudo apt install postgresql postgresql-contrib -y

2. Tạo người dùng và cơ sở dữ liệu

PostgreSQL sử dụng "roles". Các lệnh sau tạo một role mới và một cơ sở dữ liệu do role đó sở hữu.

sudo -u postgres createuser --interactive --pwprompt
sudo -u postgres createdb -O newuser newdb

3. Cấu hình xác thực (Tùy chọn, cho truy cập từ xa)

Chỉnh sửa `/etc/postgresql/<version>/main/pg_hba.conf` để cho phép kết nối bằng mật khẩu.

1. Cài đặt MongoDB (Theo hướng dẫn chính thức)

Quá trình cài đặt MongoDB yêu cầu thêm kho lưu trữ riêng. Luôn tham khảo tài liệu chính thức của MongoDB để có hướng dẫn mới nhất. Sau khi cài, hãy khởi động dịch vụ.

sudo systemctl start mongod && sudo systemctl enable mongod

2. Bật xác thực (Rất quan trọng)

Mặc định MongoDB không bật xác thực. Chỉnh sửa `/etc/mongod.conf` và thêm: 

security:
  authorization: "enabled"

Sau đó khởi động lại MongoDB: `sudo systemctl restart mongod`

3. Tạo người dùng quản trị

Kết nối vào `mongosh` và tạo người dùng quản trị đầu tiên. 

use admin
db.createUser({
  user: "myAdminUser",
  pwd: passwordPrompt(),
  roles: [ { role: "userAdminAnyDatabase", db: "admin" }, "readWriteAnyDatabase" ]
})

3. Triển khai Ứng dụng Web

Sử dụng Nginx làm reverse proxy là một thực hành tiêu chuẩn. Nginx sẽ nhận lưu lượng truy cập từ người dùng (cổng 80/443) và chuyển tiếp đến ứng dụng của bạn đang chạy trên một cổng cục bộ (ví dụ: 3000, 8080). Điều này giúp quản lý SSL, phục vụ tệp tĩnh hiệu quả và chạy nhiều ứng dụng trên cùng một máy chủ.

Luồng hoạt động của Reverse Proxy

Người dùng
→
NGINX
(Cổng 80/443)
Xử lý SSL
→
Ứng dụng của bạn
(ví dụ: localhost:3000)

Dưới đây là các cấu hình Nginx mẫu cho các loại ứng dụng phổ biến. Đừng quên cài đặt Nginx (`sudo apt install nginx`) và Certbot (`sudo apt install certbot python3-certbot-nginx`) trước.

Tạo tệp cấu hình trong `/etc/nginx/sites-available/your_domain.com`. Giả sử ứng dụng Node.js của bạn đang chạy trên cổng 3000. 

server {
    server_name your_domain.com www.your_domain.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
    
    listen 80;
}

Sau đó, kích hoạt trang, kiểm tra cấu hình và chạy Certbot: 

sudo ln -s /etc/nginx/sites-available/your_domain.com /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d your_domain.com -d www.your_domain.com

Rất giống với Node.js. Giả sử ứng dụng Spring Boot (JAR) của bạn chạy trên cổng 8080. 

server {
    server_name your_domain.com www.your_domain.com;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    listen 80;
}

Các bước kích hoạt trang và chạy Certbot tương tự như Node.js.

Nginx cần giao tiếp với PHP-FPM (ví dụ: `php8.1-fpm`). Hãy chắc chắn bạn đã cài đặt nó. Cấu hình này dành cho một framework PHP hiện đại. 

server {
    server_name your_domain.com www.your_domain.com;
    root /var/www/your_project/public;

    index index.php index.html;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/var/run/php/php8.1-fpm.sock;
    }

    location ~ /\.ht {
        deny all;
    }

    listen 80;
}

Các bước kích hoạt trang và chạy Certbot tương tự như Node.js.

4. Quản lý & Giám sát Tiến trình

Để ứng dụng của bạn chạy ổn định trong môi trường production, bạn cần một trình quản lý tiến trình. Nó sẽ tự động khởi động lại ứng dụng khi gặp lỗi hoặc khi máy chủ reboot. Hãy chọn công cụ phù hợp với công nghệ và nhu cầu của bạn.

PM2 là trình quản lý tiến trình mạnh mẽ và phổ biến cho Node.js, hỗ trợ chế độ cluster, quản lý log và giám sát.

Cài đặt:

sudo npm install pm2 -g

Sử dụng:

# Khởi động ứng dụng
pm2 start app.js --name "my-api"

# Liệt kê các ứng dụng
pm2 list

# Thiết lập khởi động cùng hệ thống
pm2 startup
pm2 save

Supervisor là một công cụ đa năng, có thể quản lý bất kỳ tiến trình nào (Java, Python, scripts...).

Cài đặt:

sudo apt install supervisor

Cấu hình:

Tạo một tệp cấu hình trong `/etc/supervisor/conf.d/my-app.conf`. 

[program:my-java-app]
command=java -jar /path/to/app.jar
autostart=true
autorestart=true
user=your_app_user

Sử dụng:

sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl status

Docker đóng gói ứng dụng và các phụ thuộc của nó vào container, đảm bảo tính nhất quán trên mọi môi trường. Docker Compose giúp quản lý các ứng dụng đa container (ví dụ: app + database).

Khái niệm:

  • Dockerfile: Công thức để xây dựng một image.
  • Image: Một khuôn mẫu chỉ đọc.
  • Container: Một thực thể chạy của một image.

Sử dụng:

Sau khi viết `Dockerfile` và `docker-compose.yml`: 

# Xây dựng và khởi chạy các container ở chế độ nền
docker-compose up -d

# Dừng và xóa các container
docker-compose down

5. Củng cố An ninh Máy chủ

Bảo mật là một quá trình liên tục. UFW (Tường lửa) và Fail2ban (Chống brute-force) là hai công cụ thiết yếu để tạo nên tuyến phòng thủ vững chắc cho máy chủ của bạn.

Tường lửa UFW

UFW giúp bạn quản lý các quy tắc tường lửa một cách đơn giản. Nguyên tắc là: chặn tất cả mặc định, và chỉ cho phép những gì cần thiết. 

# Bật UFW (hãy chắc chắn đã cho phép SSH)
sudo ufw allow ssh
sudo ufw enable

# Cho phép các dịch vụ web
sudo ufw allow 'Nginx Full'

# Kiểm tra trạng thái
sudo ufw status

Chống tấn công với Fail2ban

Fail2ban theo dõi log hệ thống và tự động cấm các địa chỉ IP có hành vi đáng ngờ, ví dụ như cố gắng đăng nhập SSH thất bại nhiều lần. 

# Cài đặt Fail2ban
sudo apt install fail2ban

# Dịch vụ sẽ tự động chạy và bảo vệ SSH mặc định

# Kiểm tra trạng thái jail của SSH
sudo fail2ban-client status sshd
